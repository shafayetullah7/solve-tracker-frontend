# Rendering, SEO, UX and resource conventions

Binding target for new frontend work and rendering migration. Existing SSR implementation is transitional; do not claim migration complete. Read with FRONTEND_CONVENTIONS.md, AUTH_CONVENTIONS.md, API_CLIENT.md and docs/DEPLOY.md. If current implementation conflicts, preserve security and document migration rather than silently changing behavior.

## Route policy
Every new route declares audience, indexing policy, rendering mode, data ownership, cache policy, loading/error states and status behavior in its design/PR. Default deny indexing for authenticated, auth, account and share-only pages. Public visibility is not consent to search indexing. Existing public people/topic routes remain noindex. Static-first: build-time HTML for stable indexable pages; CSR for private and non-indexable interactive pages; request-time SSR only for explicitly approved dynamic indexable content or demonstrated essential UX/share preview requirement. Prefer bounded regeneration where supported. No crawler-specific content. No global SSR expansion by default.

## Framework
Use installed Solid 2 RC, @solidjs/web, router and Vite plugin versions; inspect local declarations and docs before choosing client mode, prerender or hybrid APIs. No assumed SolidStart/Next configuration, new framework, dependency upgrade or duplicate application architecture without review. A static shell must mount correctly, not hydrate nonexistent markup. Keep route splitting and shared primitives.

## SEO
Indexable pages deliver complete meaningful primary content, semantic headings, crawlable links and unique title/description in initial HTML without JS or auth/API dependency for static content. Trusted configured HTTPS public origin for canonical, OG, sitemap; fail production build/config on invalid origin rather than trust Host. Appropriate OG/Twitter and accurate structured data; no duplicate/conflicting head tags. Sitemap contains only canonical indexable successful URLs; absolute sitemap URL in robots. Use initial HTML or X-Robots-Tag noindex for non-indexable documents; robots disallow is not a deindex mechanism. Preserve real 404/410 and 5xx for public missing/error pages, appropriate redirects; no universal 200 SPA fallback for unknown public paths. Preserve existing share-only privacy; no profile indexing without explicit approval. Verify raw response, JS-disabled content, metadata, links, canonical, status, sitemap and mobile rendering.

## Auth and privacy
Marketing HTML independent of session and backend health. No per-request auth probe for static pages. CSR establishes session before protected fetches; preserve HttpOnly cookies, CSRF/origin, same-origin API, one refresh coordinator, safe return paths, account epoch, logout/cross-tab invalidation. No private content or account identity in reusable shell, static output or shared cache. Preserve safe loading/unavailable states; no protected content flash, login loop or incorrect anonymous redirect during recovery. Server authorization is mandatory. Any retained server auth probe has explicit timeout/abort and measured benefit.

## Cache and delivery
Production target edge serves hashed assets (immutable long-lived), static HTML (revalidate/versioned deploy), CSR shell (generic, no secrets, noindex), /api direct same-origin backend proxy, optional SSR only on allowlisted routes. Preserve API path rewrite, cookies, trusted forwarding headers, origin, request limits and security headers. Dev proxy remains. Private/personalized HTML/API/auth redirects private,no-store; never shared cache Set-Cookie, auth bootstrap, tokens or viewer-specific data. Public SSR caching opt-in only after anonymous deterministic output, normalized bounded keys, explicit TTL/invalidation and privacy revocation proof; bypass credentials unless proven irrelevant. No stale serving after visibility revocation; fail closed. CSP for static HTML via reviewed hashes/external scripts or equivalent; never reuse per-request nonce in cached HTML or weaken CSP to enable caching. No Redis/CDN requirement by default.

## UX and client efficiency
Persistent app layout, route-level lazy chunks, intent preload with deduplication and no protected requests before auth. Parallel independent requests; dependent requests only where necessary. Account-scoped bounded cache, cancel obsolete requests, invalidate on mutation/logout/account switch, no generic mutation retries. Stable layout skeletons, independent error/retry, retain previous data during safe revalidation, no blank screens. Lazy heavy editors/charts; avoid global imports of feature code. Accessible keyboard/focus, reduced motion, 44px controls, mobile and 200% zoom. Preserve deep links, refresh, back/forward and scroll. No speculative optimization without evidence.

## Verification and budgets
Baseline and after on same pinned build, hardware, fixtures and network: raw HTML and no-JS checks; auth/redirect/privacy/cache/CSP/API contract tests; browser desktop/mobile and slow/offline tests; bundle compressed bytes per route, duplicate requests, TTFB/LCP/CLS/INP, Node RSS/CPU, backend requests per navigation, p50/p95/p99 and errors under identical load. Initial lab targets LCP <=2.5s, CLS <=0.1, interaction <=200ms (lab proxy; field INP measured separately); report device/network and cold/warm. Static/CSR document requests target zero frontend Node renders and zero server session probes. No regression in indexable content, auth/security, accessibility or navigation; document exceptions with evidence. No numeric resource savings claimed before benchmark. Existing pnpm check/build/api:check/test:e2e and deploy smoke gates retained or explicitly adapted with equivalent assertions. PR checklist: route policy, initial HTML/status/indexing, cache isolation, auth lifecycle, bundle/network evidence, UX states, tests and rollback. No production rollout until gates pass.
